# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Disk Flashlight is a Windows-only disk space analyzer (OverDisk-style sunburst chart) written in Rust with egui/eframe 0.36 on wgpu. `README.md` / `README.ru.md` are the user-facing docs and must be kept in sync (both languages, cross-linked, formal tone).

## Commands

```
cargo build --release                # binary at target\release\disk_flashlight.exe
cargo test                           # unit tests (model, layout hit-test, history, format)
cargo test layout::                  # single module's tests
cargo clippy --release               # must stay warning-free
cargo run --release -- --bench D:\   # scanner + layout benchmark, prints method, timings, top-level dirs
cargo run --release -- --bench D:\ --walk   # same, MFT scanner disabled
cargo run --release -- D:\Projects   # open the GUI scanning a path on start
```

GitHub releases: `.github/workflows/release.yml` runs `make_release.py` on `windows-latest` for tags `v*` (tag must equal `v` + Cargo.toml version, otherwise the job fails) and publishes `dist/*_Setup.exe` plus `dist/*_portable.zip` (only the exe inside a `Disk Flashlight` folder, built by `make_release.py::make_portable_zip`); `workflow_dispatch` builds an artifact only. Creating or pushing a tag publishes a public release, so do it only when the user asks.

Release: `python tools/make_release.py [--no-tests]` runs tests, `cargo build --release`, exports the icon (`disk_flashlight.exe --export-icon target\app.ico`) and compiles `tools/setup.iss` with Inno Setup 6 into `dist\`, passing the version from `Cargo.toml` via `/DMyAppVersion` (the `.iss` is not edited). The installer is per-user (`PrivilegesRequired=lowest`) and registers the context-menu verb under `HKCU\Software\Classes\{Directory,Drive}\shell\DiskFlashlight`. Explorer passes a drive as `"C:\"`, which Windows argument parsing turns into `C:"`; `main.rs::normalize` repairs it, so keep that when touching argument handling. The script fails early if `target\release\disk_flashlight.exe` is running (the file is locked).

Toolchain: stable MSVC Rust plus VS 2022 Build Tools. In the Bash tool, `cargo` is not on PATH; prefix commands with `export PATH="$HOME/.cargo/bin:$PATH"`. A running `disk_flashlight.exe` locks the release binary, so stop it before rebuilding (`Get-Process disk_flashlight | Stop-Process`).

Heredocs containing Rust code break the Bash tool (lifetime apostrophes); write source files with the Write tool or a Python script.

## Architecture

Data flows in one direction: `scan` → `model` → `layout` → `render` → `ui`.

- **`scan/mod.rs::scan`** picks the scanner: paths on local drives (`mft::drive_letter`) go to **`scan/mft.rs`** first. `mft::locate` canonicalises the path (resolving junctions and symlinks, possibly onto another volume) into a volume letter plus folder names, and `build_tree` starts from the folder's record found by those names (exact, then case-insensitive), so a folder costs a full-volume MFT read. The scanner opens `\\.\C:` raw, locates `$MFT` via `FSCTL_GET_NTFS_VOLUME_DATA`, streams the table in 8 MiB blocks on a reader thread and parses 1 KiB FILE records in parallel (fixups, `$FILE_NAME` for name/parent, unnamed `$DATA` for sizes, `$STANDARD_INFORMATION` for the last write time; extension records are merged into their base record; DOS 8.3 names skipped; hard links counted once). It needs administrator rights, so without elevation or on non-NTFS it fails and `scan` falls back to the walk, resetting progress counters. Its parsing is unit-tested on synthetic records built in the test module; testing against a real volume requires an elevated run (`Start-Process -Verb RunAs`, which shows a UAC prompt the user must confirm). The MFT result includes metafiles (`$MFT`, `$LogFile`, `$Extend`) and `System Volume Information`, so totals differ from the walk.
- **`scan/walk.rs`** walks directories under rayon, listing each with `win::list_dir`: `GetFileInformationByHandleEx(FileFullDirectoryInfo)` into a 64 KiB thread-local buffer (names, attributes, sizes, reparse tag in `EaSize`), about 40% faster than `std::fs::read_dir` on a warm cache and verified entry-for-entry against it. Symlinks and junctions (name-surrogate reparse points, the same rule as `FileType::is_symlink`) are skipped. The listing's `AllocationSize` is deliberately not used: it is stale for secondary hard links and rounded to 64 KiB for sparse files, so physical size stays cluster-rounded, with `GetCompressedFileSizeW` for compressed or sparse files. It builds a nested `RawDir` tree and reports progress through atomics in `Progress`; an unreadable folder counts in `Progress::errors` and the first `MAX_KEPT_ERRORS` are kept with the system message in `Progress::failed`, which `App::poll_scan` hands to `ui::errors::ErrorsView` (status-bar link and the "Access errors" window). `scan/mod.rs` runs it on a thread and hands the result back over a bounded channel; `scan/win.rs` wraps the few Win32 calls (drive list, cluster size, compressed size). The drive picker is filled asynchronously: `win::drive_roots` (a bitmask, instant) gives the letters, and `App::new` queries each with `win::drive_info` on its own thread, so a disconnected network drive delays only its own entry, not start-up; the selected drive is kept as its root (`App::drive`), not an index, because entries arrive in any order. Nothing is selected at start-up (the last path only fills the path field), so a slow drive is never scanned unasked. Below the drives it lists `App::recent` (folders of finished scans, `app::push_recent`: newest first, no drive roots, `same_path` duplicates dropped, `MAX_RECENT`, kept in `Settings::recent` one per line), long ones shortened by `toolbar::elide_middle`. A folder dragged onto the window is scanned by `App::handle_drop` (`raw.dropped_files`; a file scans its folder, `app::drop_target`), and `App::drop_overlay` veils the window while `raw.hovered_files` is set; drops from a non-elevated Explorer never reach an elevated instance (UIPI). The picker ends with "Choose folder…", which sets `App::choose_folder`; `App::ui` opens `rfd::FileDialog::pick_folder` there because it needs the `eframe::Frame` as the parent window (`rfd` without default features pulls only `windows-sys`, `raw-window-handle` and `log`). `windows-sys` features are kept minimal (`Win32_Foundation`, `Win32_Storage_FileSystem`, `Win32_System_IO`, `Win32_UI_Shell`); `DRIVE_*` constants are hard-coded to avoid another feature. `win::relaunch_elevated` restarts the app via `ShellExecuteW("runas")`; arguments go through `app::quote_arg` because `CommandLineToArgvW` treats `\"` as an escaped quote.
- **`icon.rs`** draws the app icon procedurally with no dependencies; `build.rs` includes it via `#[path]` to write a multi-size `.ico` and embeds it with `winresource`, and `main.rs` uses the same pixels for the window icon.
- **`model.rs`** packs the raw tree into an arena `Vec<Node>` in DFS order. `Node::modified` is the last write time as `u32` Unix seconds (0 = unknown; it sits in former padding, `Node` stays 48 bytes, checked by a test); `RawDir::finalize` gives a non-empty folder the newest time in its subtree, not its own. The walk takes it from `FileFullDirectoryInfo::LastWriteTime` (the root from `metadata`). `Model::scanned_at` is the reference point for ages (colours, the age filter, "N days ago") and survives `Model::without`. `format::date` shows local dates through `win::utc_offset` (`FileTimeToLocalFileTime`, no extra `windows-sys` feature). Every node's children are a contiguous range **sorted by logical size descending**, and names live in one string arena. This ordering is what makes "largest first" free downstream; anything that iterates children may rely on it. For the physical metric the order can differ slightly, so layout and the tree re-sort a copy when `Metric::Physical` is active.
- **`layout.rs`** converts a subtree rooted at any node into rings of `Sector { node, a0, a1 }` (angle 0 = top, clockwise). The number of rings is `LayoutParams::max_depth` (`layout::MIN_RINGS..=MAX_RINGS`, default 7), chosen in the toolbar's Rings list or with `+`/`-` (`App::set_rings`) and kept in `Settings::rings`. Ring radii follow a geometric series whose ratio comes from `rim_ratio` (outermost ring thickness / first), so the rim stays readable at any count. The first child whose arc is shorter than `merge_arc_px` and all smaller ones become one group sector (`Sector::count > 0`, `node` = the parent, `group_size`; a single leftover is drawn as itself; groups under `min_arc_px` are dropped). `build` also takes the visible rect: `ViewBounds` (polar r range + angular range) culls sectors and whole subtrees off screen, and `render` tessellates only the visible pieces (`ViewBounds::clip`), so work stays bounded by the window even at 200x zoom. `build_with_free` (used by the chart) adds the drive's free space as one more ring-0 sector after the root's children (`Sector::is_free`: `node == NO_NODE`, bytes in `group_size`; `App::disk` is queried at scan end only for volume or share roots and passed only while the scan root is centred); code that needs a real node must check `Sector::is_item`. Files (`Sector::is_file`) are drawn inset from their folder, OverDisk-style: `Layout::sector_radii` moves their inner radius out by `LayoutParams::file_inset` of the ring (at least `file_inset_min_px`), and everything that draws a sector (mesh, hover overlay, outline) must use it instead of `radii`; hit testing keeps the whole ring. `Layout::hit_test` finds the ring by radius and binary-searches the angle; `Layout::index` maps node id → sector for external highlighting (groups are not indexed).
- **`render.rs`** tessellates all sectors into a single `egui::Mesh` (one draw call) and defines the palette. Two modes (`ColorMode`): **Size** (default, OverDisk's size-encoded scheme) takes the hue from `Sector::rel`, the size relative to the largest sibling computed in `layout::emit` (largest = red, small = yellow), and fades saturation towards white linearly with ring depth; **Depth** takes the hue from the ring (`Palette::hues` stretched over `Palette::rings`, which `build_mesh` sets from the layout) and alternates brightness. **Age** takes the hue from `Palette::age_t` (log scale, red = now to blue = `age_span_days`), with half the depth fade and grey for unknown times; `ui::chart::age_legend` draws its scale in the chart's bottom left corner. Files get lower saturation in all modes. Colours go through egui's linear-space `Hsva`, which is what makes them pastel; the user wants to keep that. `Palette::for_theme(dark)` holds every chart colour (background, guides, centre disc, hover outline, legend) for the light and the dark theme; `ChartView::show` swaps it when `ui.visuals().dark_mode` changes, keeping the colour mode, and the cache key carries the theme. The dark palette is deeper (`val_even` 0.62), fades brightness with depth as well as saturation (`fade_val` 0.7, `fade_max` 0.45: linear-space dimming barely shows in sRGB, so it has to be strong for neighbouring rings to stand apart), stops the size hue at gold (yellow turns olive when dark) and keeps groups dark (`val_group`). The theme itself is `egui::ThemePreference` (System by default) set with `Context::set_theme`, switched by `toolbar::theme_button` and kept in `Settings::theme`; Windows 10 does not repaint the caption when winit changes its dark-mode attribute, so `App::follow_theme` notices a theme change and on the next frame calls `win::refresh_caption` (`WM_NCACTIVATE` off and on, user32 declared by hand); other theme-dependent colours are `files::MARK_BG_DARK` and `ui::danger_text`. Helper shapes for hover outlines and guide circles live here too.
- **`ui/chart.rs`** owns the cached `Layout` + `Arc<Mesh>` keyed on (root, metric, centre, radius, view rect) and rebuilds only when the key changes (every frame while panning or zooming, which is cheap thanks to culling). It draws the chart, handles hover (instant `Tooltip::always_open`, not the delayed `on_hover_ui`), wheel zoom towards the cursor (`zoom`, up to 200x), middle-button panning (`pan`, reset on root change, middle double click or the corner `reset_button` shown while zoomed or panned, which also hides the chart's hover under it), click-to-navigate and click-on-group-to-zoom, returning a `ChartAction` for `App` to apply.
- **`ui/tree.rs`** is a virtualised directory-only tree (`ScrollArea::show_rows`) with its own expanded set; `reveal()` runs on every root change and replaces the expanded set with the new root and its ancestors, so expansions (manual ones included) do not pile up while navigating. With Follow in tree, `TreeView::follow` peeks: the ancestors of the directory hovered in the chart are expanded temporarily (`peek`), and the peek folds when the pointer is on the chart but on no sector (`ChartView::pointer_inside`), not when it leaves the chart, so it can move into the tree. Expand/collapse arrows are painted as triangles because the default fonts lack ▲/▼ glyphs.
- **`ui/files.rs`** is the "Largest files" tab of the left panel (`ui::SideView`): `Model::largest_files` (min-heap of the top 100 under the current root, optionally only files modified before a cutoff; directories no larger than the smallest kept file are skipped) cached per (root, metric, age filter, order). `ListSort` (size, oldest, newest) reorders the top N of both lists; the date column appears only when a list is ordered by date or filtered by age. It returns the tree's `TreeAction`: a click selects the file and navigates to its parent, and the file stays selected there because a top-100 file of a folder is also top-100 in its own subfolder.
- **`ui/search.rs`** is the "Search" tab (`Ctrl+F` switches to it and focuses the field): `Model::search` over the whole scan (not the centre, so navigating from a result does not change the list), the query is split into `model::Term`s at spaces (`"..."` keeps a phrase) that must all match, `|` or `;` joining alternatives within one (Everything's precedence): a case-insensitive substring, or a whole-name mask when the term has `*`/`?` (`model::wildcard`), optionally limited to files or folders (`model::ItemKind`, the field's page/folder toggle, `Settings::search_kind`) and whole words for substrings (the field's "ab" toggle, `Settings::search_whole_word`; only ends of the term that are word characters are checked, so `.py` skips `.pyd`); `model::Lowered` lowercases a non-ASCII name once for all terms; `model::match_ranges` gives the matched byte ranges of a listed name for the highlighter background in `files::item_row` (masks are not marked); an ASCII query compares bytes, a non-ASCII one skips pure-ASCII names and lowercases the rest (C:\ with 917k nodes: 12-35 ms per keystroke, timed by `--bench`; `*.ext` masks are cheaper thanks to `wildcard` checking the part after the last `*` against the end of the name first, other masks up to twice as slow). `Found::total` sums matches without counting anything inside a matching folder twice. `Found::hits` (matching bytes per node) colours the chart while the Search tab is open: `render::build_mesh` takes it, `Palette::highlight` fades by `render::match_share`, and `ChartView`'s cache key carries `SearchView`'s generation. A group's items are found through `Sector::first` + `Sector::group_has`, which relies on layout ordering children by size descending, then by id, for both metrics. Rows are drawn by `files::item_row`, shared with the Largest files tab; `TopN` in `model.rs` keeps the N largest for both.
- **`types.rs`** gives every file a type (its lowercase extension, `types::extension`; `NO_EXTENSION` = 0, folders `NOT_A_FILE`) in `Model::types`, built at the end of `Model::from_raw` (C:\ with 923k nodes: 20 ms). `FileTypes::stats` totals a subtree (3 ms for C:\), `FileTypes::hits` gives per-node matching bytes for colouring like search matches, summing from the last node back because a parent is always packed before its children, and `rank` puts the `COLOURED` (12) largest types of the whole scan by logical size into colour slots, so colours stay put while navigating. **`ui/types.rs`** is the Types tab (`SideView::Types`): rows cached per (root, metric), Windows descriptions from `win::type_description` (`AssocQueryStringW`, `ASSOCSTR_FRIENDLYDOCNAME`) cached per type; a click selects the type for `TypesView::highlight`, a double click asks `App` to open Search with `*.ext`, and the arrow unfolds its `FILES_SHOWN` largest files (`Model::largest_files_where`, cached per type until the root or metric changes) as `Line`s of one flat, virtualised list; the files behave as in the other lists through the `TreeAction` in `TypesAction`. Highlights of Search and Types take their generation from `ui::next_generation`, one counter, because the chart cache key holds only the number. `ColorMode::Type` paints files with `Palette::type_color` (hue plus a brightness factor per slot: twelve pastel hues alone are too close) and folders `type_folder`, with `chart::type_legend`.
- **Context menu and deletion**: `ui::item_menu` is the one context menu (Open in Explorer, Properties, Copy path, red Delete…) used by the chart, the tree and both lists, returning a `ui::ItemCommand` that `App::run_command` carries out. `Ctrl+C` reaches egui as `Event::Copy`, not as a key press; `App::handle_keys` turns it into Copy path for the hovered item or the centre. Delete opens a confirmation `egui::Modal` (`App::show_confirm_delete`), then `win::recycle` (`SHFileOperationW` with `FOF_ALLOWUNDO`, the shell's own progress and permanent-delete warning) runs on a thread; `App::poll_delete` checks what is left on disk and, if the item is gone and the model is unchanged, installs `Model::without(id)` (a rebuilt copy, ~20 ms per 170k nodes) through `App::set_model`, which a finished scan uses too and which remaps history by path. Ids change on every model swap, so `ChartView::invalidate` clears `hovered`. `App::start_scan` drops the model at once (`App::clear_model`, spinner screen) when the new path differs from the current one (`same_path`: case and trailing backslash ignored); a rescan of the same path keeps it on screen.
- **`ui/toolbar.rs`** implements toolbar and status bar as `impl App` methods. Its path field is **`ui/path_field.rs`**: a label with the current path that becomes a text field on a click (Explorer-style), with a suggestion list of drives or of the typed folder's subfolders (`read_dir` once per folder, cached; network paths, `app::is_remote`, are never listed so a dead server cannot stall the UI); arrows and Tab/Enter are consumed before the `TextEdit` while the list is open. `App::start_scan` rejects a local path that is missing or not a folder before touching the current results, and `walk::scan` fails on such a root instead of producing an empty model. **`app.rs`** is the eframe `App` (note egui 0.36 API: `fn ui(&mut self, ui, frame)` with `egui::Panel::top/left/bottom(...).show(ui, ...)` and `CentralPanel::no_frame()`, not the older `update(ctx)` / `SidePanel` API). Navigation state is `history::History` (root, back, forward), kept UI-free so it is unit-testable.
- **`settings.rs`** holds what survives a restart (metric, colour mode, Follow in tree, last path) as plain strings in eframe's storage (`persistence` feature, `%APPDATA%\Disk Flashlight\data\app.ron`, no serde derives needed); `App::new` applies it and `App::save` writes it. eframe itself persists the window geometry and egui memory (panel widths). `NativeOptions::centered` is set only when no `app.ron` exists yet, because eframe would otherwise re-centre a restored window. GUI tests that change settings leave them in that file, so restore it afterwards.

## Conventions

- The interface is in English and Russian (`i18n.rs`). Every user-visible string goes through `tr!("English", "Русский")`, which picks by the current language and evaluates only that arm (so `format!` in both arms is fine); counts with words use `i18n::count` / `files` / `folders` (Russian has three plural forms, `i18n::ru_plural`), sizes, percentages, dates and ages come from `format` (`_in(lang, …)` variants for tests, which must not rely on the global language). The language is a global atomic set from `Settings::language` (`LangChoice`: System follows `win::ui_language_is_russian`, `GetUserDefaultUILanguage`, hence the `Win32_Globalization` feature) in `App::new` before any text is made, and changed from the About window. Log messages, CLI output (`--bench`, `--help`) and technical scanner errors stay English.

- Commits in this repository end with a `Co-Authored-By:` trailer naming the Claude model doing the work, e.g. `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>` (this overrides the global "no Co-Authored-By" rule for this repo only).
- Keep the model and layout allocation-free on hot paths; the chart must stay responsive on ~1M-node trees (reference: C:\ with 917k nodes scans in ~8.5 s cold, layout + mesh ≈ 1 ms).
- The version comes from `Cargo.toml` via `main::VERSION` and appears in the window title (`Disk Flashlight 0.1.0`), `--version`, the exe version resource and the installer; bump it only in `Cargo.toml`. Match the window by title prefix, not exact title. The release exe is GUI-subsystem, so CLI modes (`--bench`, `--version`, `--help`) call `AttachConsole` to print when run from a console.
- `--mft [PATH]` (`main::elevate_for_mft`) relaunches elevated via `win::relaunch_elevated` with the same path and exits, using the same usefulness rule as the Fast scan button (a path on a local NTFS drive, or no path); otherwise, or if UAC is declined, it starts normally. An elevated instance cannot be stopped or captured with PrintWindow from the non-elevated tool shell (UIPI); read its window with `CopyFromScreen` and ask the user to close it.
- Start-up white flash: winit shows a window created maximized at once (`ShowWindow(SW_MAXIMIZE)`), defeating eframe's hidden-until-first-frame start. `NativeOptions::window_builder` in `main.rs` therefore creates a restored maximized window as a normal one (same size) and sets `MAXIMIZE_WHEN_SHOWN`; `App::ui` sends `ViewportCommand::Maximized(true)` from the second frame on. Keep it when touching window options; check with a pixel probe at start-up, not with PrintWindow.
- Node ids are `u32` indices; `NO_NODE` (`u32::MAX`) is the null parent. Root of a scan is always id 0.
- The chart mesh has no edge feathering; smoothing comes from `NativeOptions::multisampling = 4` (override with env `DF_MSAA`, e.g. `DF_MSAA=1` to compare). The centre disc is drawn as a mesh too (`render::disc_mesh`), because egui circles use a fixed segment count and look polygonal at high zoom.
- Palette and layout tunables are grouped in `render::Palette` and `layout::LayoutParams` rather than scattered as literals.
- GUI checks: capture the app's own window with `PrintWindow` (no focus change). Before any simulated mouse/keyboard input, warn the user so they keep their hands off the machine.
