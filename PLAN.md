# Disk Flashlight — аналог OverDisk на Rust

## Контекст

Нужен анализатор занятого места на диске в стиле OverDisk: в центре текущая директория, вокруг — кольца поддиректорий и файлов (sunburst), внутри каждого кольца элементы отсортированы по убыванию размера (крупные идут первыми по часовой стрелке). Главные требования: скорость сканирования и плавная отрисовка диаграммы даже для дисков с сотнями тысяч объектов.

Директория `D:\Projects\disk_flashlight` пуста — проект с нуля.
Решения, принятые с пользователем: **Rust + egui/eframe (wgpu)**, **только Windows**, объём **MVP** (диаграмма + дерево + tooltip + навигация). Установка инструментов разрешена.

## Стек

| Назначение | Инструмент |
|---|---|
| Язык | Rust (stable, MSVC toolchain) |
| GUI/рендер | `eframe`/`egui` (последняя стабильная, backend `wgpu`) — custom `Mesh` для секторов |
| WinAPI | `windows-sys` (FindFirstFileExW, GetDiskFreeSpaceW, GetLogicalDrives, GetCompressedFileSizeW) |
| Параллелизм | `rayon` (обход директорий), `crossbeam-channel` (прогресс скан → UI), `parking_lot` |
| Прочее | `anyhow`, `log`+`env_logger`, `winresource`/`embed-resource` (иконка, позже) |
| Позже | `ntfs` crate — чтение сырой MFT под админом (сканирование ТБ-диска за секунды) |

Установка (winget):
```
winget install Rustlang.Rustup
winget install Microsoft.VisualStudio.2022.BuildTools --override "--wait --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```
Запасной вариант без Build Tools: `rustup default stable-x86_64-pc-windows-gnu` (mingw идёт в комплекте с rustup, egui/wgpu собираются).

## Архитектура

```
Cargo.toml

src/scan/mod.rs      – trait Scanner, ScanProgress, запуск в фоне
src/scan/walk.rs     – параллельный обход FindFirstFileExW (MVP)
src/scan/mft.rs      – (фаза 5) сырое чтение MFT
src/layout.rs        – дерево + корень → Vec<Sector{node, depth, a0, a1}>
src/render.rs        – тесселяция секторов в egui::Mesh, палитра, hit-test
src/ui/toolbar.rs    – диски, Rescan, Back/Forward/Up, Physical/Logical
src/ui/tree.rs       – левая панель, виртуализированное дерево
src/ui/chart.rs      – виджет диаграммы: paint mesh, hover, tooltip, клик

```

### Модель данных (ключ к скорости)
- `Node { name: (u32 offset, u16 len) в общий String-arena, size: u64, alloc: u64, parent: u32, children: Range<u32>, files: u32, dirs: u32, is_dir: bool }`.
- После сканирования дерево **перепаковывается в DFS-порядке с детьми, отсортированными по убыванию `size`** → дети любого узла — непрерывный slice, поддерево — непрерывный диапазон. Это даёт: сортировку «крупные первыми» бесплатно при layout, агрегаты одним проходом снизу вверх, отсутствие аллокаций при обходе.
- Два размера у узла: логический (`size`) и физический (`alloc` = round-up до кластера тома из `GetDiskFreeSpaceW`; для compressed/sparse — `GetCompressedFileSizeW`). Переключатель Physical/Logical меняет только поле, по которому считается layout.

### Сканер (MVP)
- Рекурсивный обход через `FindFirstFileExW(FindExInfoBasic, FIND_FIRST_EX_LARGE_FETCH)` — даёт имя, атрибуты, размер за один вызов, без открытия файлов.
- Параллелизм: `rayon` — каждая поддиректория → задача; результаты собираются в локальные `Vec<Node>` с временными id, затем сливаются в единую арену (merge за O(n)).
- Reparse points (symlink/junction) не входим, чтобы не зациклиться. `$RECYCLE.BIN`, `System Volume Information` — сканируем, ошибки доступа считаем и не падаем.
- Прогресс: атомарные счётчики файлов/байт, UI опрашивает раз в кадр; по завершении — atomic swap `Arc<Model>`.
- Цель: ~1M файлов на прогретом кэше ≤ 5 с, на холодном ≤ 30 с (NVMe).

### Layout
- Вход: модель, id корня, метрика (size/alloc), радиус центра `r0`, толщина колец, максимальная глубина `D` (5–7, как в OverDisk), минимальный угол в пикселях.
- Рекурсия от корня: угловой интервал родителя делится между детьми пропорционально размеру; дети уже отсортированы по убыванию → крупные первыми. Сектор с длиной дуги < 0.7 px не создаётся и не раскрывается (остаток интервала остаётся визуально пустым, как в OverDisk). Это ограничивает число секторов реально видимыми (~5–20k), а не размером дерева.
- Выход: `Vec<Sector>` сгруппированный по кольцу, внутри кольца отсортирован по углу → hit-test = кольцо по радиусу + бинарный поиск по углу, O(log n).
- Layout пересчитывается только при смене корня/метрики/размера окна; хранится в `ViewState`.

### Рендер
- Из `Vec<Sector>` строится один `egui::Mesh` (треугольники между r_in и r_out, число сегментов ∝ длине дуги, минимум 2). Тонкие разделители между секторами — небольшой угловой отступ (gap в пикселях), а не отдельные линии. Внешние кольца тоньше внутренних (как на скриншоте: коэффициент ~0.75 на уровень).
- Mesh кэшируется и перерисовывается без пересборки; hover — отдельный маленький overlay-mesh для одного сектора. Итого ~1 draw call на кадр, 60 fps независимо от размера диска.
- Палитра: оттенок по глубине от корня (красный → оранжевый → жёлтый, как в OverDisk) и лёгкое чередование яркости между соседями; файлы — отдельный оттенок. Значения в одном месте (`render.rs::palette`), чтобы менять.
- Центральный круг: имя корня (`T:`), при hover — имя сектора, размер, кол-во dirs/files в tooltip у курсора.

### UI
- `SidePanel::left` — дерево: только директории, ленивое раскрытие, `ScrollArea::show_rows` для виртуализации (только видимые строки). Клик на узел → корень диаграммы; hover в диаграмме подсвечивает узел в дереве (если раскрыт).
- `TopBottomPanel::top` — выбор диска (`GetLogicalDrives`), Rescan, ◀ ▶ ▲, Physical/Logical, путь текущего корня.
- `CentralPanel` — диаграмма. ЛКМ по сектору директории → сделать корнем (с записью в историю), ПКМ/клик по центру → вверх. Колесо — масштаб радиуса.
- `TopBottomPanel::bottom` — строка статуса: Dirs / Files / Size / Alloc для корня и для hovered.

## План по фазам

**Фаза 0 — окружение (≈0.5 ч)**
1. Установить rustup + Build Tools (или gnu target), `cargo new disk_flashlight`.
2. Подключить eframe с `wgpu`, пустое окно «Disk Flashlight», проверить сборку release.

**Фаза 1 — модель и сканер (≈1 день)**
3. `model.rs`: арена, string-arena, `repack_sorted()` (DFS + сортировка детей по size desc), агрегаты.
4. `scan/walk.rs`: параллельный FindFirstFileExW-обход, alloc по кластеру, счётчики прогресса, обработка ошибок доступа.
5. Временный флаг `--bench <path>`: сканирует и печатает время, число узлов, top-10 директорий. Замер на `C:\` и `D:\`.

**Фаза 2 — диаграмма (≈1–2 дня)**
6. `layout.rs`: секторы с обрезкой по минимальному углу, ограничение глубины, группировка по кольцам.
7. `render.rs`: тесселяция в Mesh, палитра, hit-test.
8. `ui/chart.rs`: отрисовка, hover, tooltip (имя, размер, dirs, files), центральная надпись.
9. Тест на синтетическом дереве (1M узлов, случайные размеры): время layout+mesh, fps.

**Фаза 3 — навигация и дерево (≈1 день)**
10. Клик по сектору → новый корень; история Back/Forward, Up; путь в тулбаре.
11. `ui/tree.rs`: виртуализированное дерево, синхронизация с диаграммой в обе стороны.
12. Выбор диска, Rescan, фоновое сканирование с прогрессом и подменой модели.

**Фаза 4 — доводка MVP (≈0.5–1 день)**
13. Переключатель Physical/Logical, строка статуса, горячие клавиши (Backspace — вверх, F5 — rescan).
14. Иконка, `#![windows_subsystem = "windows"]`, release-профиль (lto, opt-level 3, codegen-units 1).
15. README на английском и русском с перекрёстными ссылками (формальный стиль, без императивов).

## Проверка

- `cargo run --release -- --bench D:\` — печатает время и счётчики; сравнить число файлов с `Get-ChildItem -Recurse | Measure-Object`.
- Запуск GUI, сканирование `C:\`: диаграмма появляется, сектора внутри кольца идут по убыванию размера по часовой стрелке; tooltip совпадает с данными дерева и Проводника.
- Плавность: включить `egui` frame-time (отладочный оверлей) — ≥ 60 fps при hover, смена корня < 16 мс на дереве в 1M узлов.
- Граничные случаи: диск без прав на часть папок, junction-циклы (`C:\Users\...\Application Data`), пустая директория, файлы > 4 GB, длинные пути (`\\?\` префикс).
